How long a ban lasts

Each repeat finding within the strike window moves the address one step down this list. The first step is the one a mistake lands on, so it is kept short on purpose; the steps after it assume the address came back and did it again.

These are never banned, whatever the score: addresses that have authenticated before, the global whitelist, the admin allow-list, the GeoIP whitelist, and IPv6 — the ban path is IPv4 only. Turning enforcement back off lifts every ban it applied.

First step: a page instead of silence

On the first step of the ladder HAProxy answers the address with a page that names it, the time and a request code, instead of dropping its connections, so a person taken for a scanner can tell you and you can lift the ban. An address that goes on to signatures on two different paths while it is shown the page is taken to the next step at once; from the second step on the address is cut off before HAProxy, as before.

First-request shield

A ban arrives after the request that earned it has been answered. With the shield, HAProxy itself answers 404 to the signatures one request is banned for — an .env file, a git store, a database dump — so the first request gets nothing either. It acts only in Enforce mode, follows the same rules and exceptions as the bans, and never refuses a signed-in, whitelisted or admin address.

The adaptive protection engine is not answering, so no findings can be shown. HAProxy traffic is not affected.
