Import a certificate or an authority

One field for all of it. Choose a PEM, a DER file, or a PKCS#12 bundle (.p12/.pfx) and it is read to find out what is inside: certificates that are authorities go to the trust store below, and an end-entity certificate that arrived with its private key becomes a server certificate. Nothing is installed until you have seen what was found.

Standby certificates

A second certificate for a name, from another authority, kept ready in case this one cannot be renewed.

HAProxy resolves a name to exactly one certificate and never looks at the dates: given an expired one and a good one in the same directory it serves the expired one, and the site is down while the replacement sits unused. So a standby is kept out of that directory and put into service deliberately, from here. Nothing switches on its own — the certificate that takes over is usually signed by an authority most visitors do not carry, and that trade is yours to make, not a timer's.

While a name is on a standby it is held there. Renewal, a configuration apply and the orphan sweep all leave it alone, so the switch is not undone behind your back. Hand it back when Let's Encrypt is working again.

Keep a standby

One file holding the key and the chain together is the usual shape and is all that is needed; the second field is only for material that came as two files. Order does not matter and a file given twice is not counted twice. Checked before it is accepted: the key has to match the certificate and the certificate has to cover the name — a standby discovered to be broken at the moment it is needed is worse than none. A wildcard filed against every name it covers is stored once per name, so each can be put into service on its own.
